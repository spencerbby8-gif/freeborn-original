# Support, reporting and guidance — local checkpoint

## What changed
Help & Support now distinguishes reporting a member (profile action into the existing moderation route) from sending a support request (ticket/outbox workflow). The support form offers eleven fixed topics and free-text details. The server validates any supplied topic and prefixes its fixed label to the existing message before inserting; this keeps older clients and the existing support/email workflow compatible without a migration. The topic is text, not an independently indexed database category, and does not route or prioritize automatically. Member reports retain the existing eight reasons and now allow optional details; the route rejects cross-origin requests and malformed profile IDs. Neither form promises a human review time or email delivery.

The member's most recent 25 support requests show full reference, readable status/forwarding state, original message and support replies with direction and timestamps. The existing owner-scoped GET remains the authority. A direct Settings link opens the welcome/navigation guide. Safety copy no longer promises immediate universal blocking given the separately documented Realtime release blocker.
