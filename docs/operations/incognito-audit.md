# Incognito and privacy controls — local source audit, not acceptance

The active Settings UI does not offer an incognito or discovery-pause switch. The settings API nevertheless reads and accepts both boolean fields without a membership entitlement check (`src/app/api/settings/route.ts`). The membership screen describes a planned, not purchasable offering. No new switch or paid entitlement is introduced in this checkpoint: exposing a privacy promise before verifying all access paths would be unsafe.

Current source has meaningful but non-identical checks. The discovery route excludes paused profiles and excludes incognito owners except a prior `like`/active-match exception; its own audit note explains why the liker exception is unreachable in the deck after prior-swipe filtering. The direct profile route applies pause/incognito but accepts any existing match row for the incognito exception, not only an active one; its other checks, including blocking, remain separate. The profile-photo chat-media route and the historical 20261109202434 RLS predicate use active matches and ordinary `like`, not every historical match or `superlike`. Former chat participants retain access to previously shared conversation attachments by design. Source represents older bare profile-photo paths through a **public** Storage URL and passes legacy external URLs through, so a person with an already known public URL may access those bytes outside the application authorization path. No claim is made here about the current production bucket configuration, current RLS catalog, previously downloaded data, or every route.

Existing local `scripts/prototype/discovery-local-db.mjs` and `discovery-privacy-contracts.mjs` cover selected discovery cases, not all direct profile, public URL, former-match, hosted RLS, concurrent change or entitlement behavior. Before exposing incognito: agree exact audiences including former matches, superlikes, blocks, public/legacy images and snooze; verify current production/preview configuration and anonymous/custom-client reads without real members; design migration/backfill/private-storage and cache handling if needed; implement and independently test all paths and enforcement; decide product entitlement. A UI label alone cannot make already public or saved bytes private.
