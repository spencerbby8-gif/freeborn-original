## Auth events

- Email/password sign-in, immediate-session account creation, confirmed signup OTP and successful password update now queue a predefined generic success event for the app or onboarding page. They use the existing Freeborn popup rather than a legacy native banner.
- The local browser previously demonstrated that the old popup disappeared during full-page navigation (`auth-banner-before.log`). The new tab-local handoff contains only a fixed event kind, session user ID, target and timestamp; no email, token, arbitrary body or profile detail. On the destination, it verifies the current local session identity, consumes once, and uses a fixed copy. Wrong-account, malformed, expired, future and unknown records cannot produce a success. Session storage failure never blocks authentication; in that case destination feedback is best effort and may be lost.
- Exactly-once applies only to a single tab's successfully consumed record. Browser tab cloning can copy session storage; storage clearing, session failure, a redirect chain (e.g. onboarding immediately redirects again), no JavaScript, errors and navigation races can lose the notice. The notice is informational, not authentication or authorization proof. The code does not change session issuance, onboarding gate or Supabase.
- Reset and resend responses now ask the member to check their inbox **if eligible**; a successful API request is not evidence of provider delivery. Signup OTP screen no longer states a code definitely arrived. Status query parameters are caller-controlled; the `verified`, `recovered`, `password-updated`, `signed-out` and `suspended` text is conditional instead of asserting account state. These notices do not make or verify state changes. Pending/callback failures retain their own existing UI.
- Google OAuth and email-link callback enter through a separate callback page; this handoff is not wired there and the actual OAuth/email-link path remains unverified. Recovery, resend and invalid credentials still require real provider-specific acceptance tests in a controlled environment; no actual messages were sent. Resend timer, spam filtering and provider delivery are not proved by intercepted browser tests.
- Auth error, CAPTCHA, duplicate-account, password breach, recovery request, resend, and callback error/expiry use a mix of inline form notices and top popups. Authentication's server-provided status is rendered inline and mirrored into a top popup; the duplicate accessibility announcement and every event's visual treatment need further review.
